# Subversion & Repository Notes (`code/doc/subversion_notes.html`)

## Overview
`code/doc/subversion_notes.html` is an HTML-formatted developer reference document created by Jonathan Beaudoin (December 2009) during the migration of the UNB Ocean Mapping Group C codebase into a centralized Subversion (`svn`) repository hosted on `mclintock.omg.unb.ca`.

---

## Key Topics Covered

### 1. Repository Creation & Initial Import
* Installing `subversion` and `subversion-tools`.
* Initializing the repository store:
  ```bash
  svnadmin create /home/jonnyb/projects/subversion_test_run/svn/omg
  svn import code_20091015 file:///home/jonnyb/projects/subversion_test_run/svn/omg/ -m "This is a test"
  ```
* Checking out a working copy over SSH from client workstations:
  ```bash
  svn checkout svn+ssh://jonnyb@mclintock.omg.unb.ca/home/jonnyb/projects/subversion_test_run/svn/omg
  ```

### 2. Interactive Conflict Resolution (`svn update`)
Walks through a concrete conflict scenario in `JV/jview.c`:
* Using `df` (`diff-full`) at the `svn update` prompt to inspect three-way diffs between the base revision, `.mine`, and the incoming repository revision.
* Using `e` (`edit`) to open `vi`, locate `<<<<<<< .mine` markers, merge the conflicting lines, remove the markers, and press `r` (`resolved`) followed by `svn commit`.

### 3. Postponed Conflict Resolution (`--accept working`)
Explains the four files generated when choosing `(p) postpone` on a conflicted file such as `JV/jview.c`:
* `jview.c` — Working file containing inline `<<<<<<<`, `=======`, `>>>>>>>` conflict markers.
* `jview.c.mine` — The developer's local working file prior to `svn update`.
* `jview.c.r9` — The baseline revision before local modifications (`base`).
* `jview.c.r10` — The latest revision fetched from the repository (`theirs-full`).

Once manually merged into `jview.c`, the developer runs:
```bash
svn resolve --accept working jview.c
svn update
svn commit
```
to clean up the temporary `.mine`/`.r*` sidecar files and commit the merged source.
